# App Store 2.4.5 拒审修复与重新提审方案

日期:2026-07-03
拒审:Guideline 2.4.5 – Performance (Hardware Compatibility)
Submission ID: 3b0a34a0-36e1-4a0d-b683-2176f735135c(1.0 (1),2026-06-22 审核)

## 拒审原因

审核员发现 app 请求 Accessibility(辅助功能)权限用于监听键盘/鼠标事件,
属于非无障碍用途,违反 2.4.5。

根源:被拒的 1.0 (1) 包由早期代码构建,其中 `MouseEventTap`
(commit 52e6bd5)使用 `CGEventTap` 做全局鼠标监听。listen-only
event tap 同样会触发系统 Accessibility 授权弹窗。

## 现状(master @ 4a7555c 之后)

已无需改代码,master 本身干净:

- 鼠标采集:f297380 起改为免权限轮询(`CGEvent(source: nil)` 读位置
  + `NSEvent.pressedMouseButtons` 读按键状态),不触发任何授权。
- 全树无 `CGEventTap` / `AXIsProcessTrusted` / `addGlobalMonitor` /
  `IOHIDRequestAccess` 等 Accessibility/Input Monitoring 触发点。
- entitlements 仅含:app-sandbox、audio-input、
  files.user-selected.read-write、assets.movies.read-write、
  network.client,全部合规。

## 决策

选择最小修复路径:从干净的 master 直接重新打包提审,
编辑器分支 `codex/post-recording-editor` 不合入,留待 1.1。

## 步骤

1. **版本号**:app target build 4 → 5,marketing 保持 1.05
   (与官网 DMG 版本一致)。提审时在 App Store Connect 将
   版本字符串从 1.0 改为 1.05 后关联新 build。
2. **本机验证**:
   - `tccutil reset Accessibility fudan.miniS.SmartRecord`
   - Archive Release 包,跑完整录制 → 导出流程
   - 确认:全程无 Accessibility 弹窗;系统设置 > 隐私与安全 >
     辅助功能列表中不出现 SmartRecord
   - `codesign -d --entitlements - SmartRecord.app` 核对 entitlements
3. **提审**:上传新 build;在 Resolution Center 回复审核员,
   说明已移除 CGEventTap 事件监听、鼠标位置采集改用无需授权的
   轮询 API、app 不再请求任何 Accessibility 权限。
